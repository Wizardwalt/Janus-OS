# Janus Repository Audit — README vs. Implementation

Audit date: 2026-11-05 · Branch: `arena/26eb9c3d-janus-os`

This records what was actually tested, what was found broken, what was fixed, and
what remains unfinished. Simulated capability is never reported as working.

---

## 1. Environment constraint (real blocker)

**The Rust build and test suite could not be run in this sandbox.**

| Requirement | Result |
|---|---|
| Rust toolchain (`cargo`, `rustc`) | Not installed |
| `static.rust-lang.org`, `sh.rustup.rs` | Blocked (TLS connection refused) |
| `index.crates.io`, `static.crates.io`, `crates.io` | Blocked — dependencies cannot be fetched |
| Debian mirrors (`deb.debian.org`) | Blocked — `apt-get update` fails |
| GitHub release assets | Blocked (`release-assets.githubusercontent.com`) |
| `github.com`, `api.github.com`, `codeload.github.com` | Reachable |
| `registry.npmjs.org`, `pypi.org` | Reachable |

Every Rust change in this patchset is therefore **statically reviewed but not
compiler-verified**. To reduce that risk, dependency versions and checksums in
`Cargo.lock` were validated against the real crates.io index (fetched through the
GitHub API), and the `mlua` 0.9.9 / `axum` 0.7.9 / `reqwest` 0.11.27 API signatures
used were checked against upstream sources at those exact tags.

**Run `./scripts/verify.sh` on Replit to execute the Rust suite.** It reports
skipped checks as skipped, never as passed.

### What *was* executed here

A real Lua 5.4 interpreter (`wasmoon`, WebAssembly build) was installed from npm,
so Lua behaviour, scope enforcement, and sandbox hardening were genuinely tested.

## 2. Findings and fixes

### Stage 1 — Lua compile failures (FIXED, verified)

Baseline compile check of all 10,631 `.lua` files found **4 files that could not
compile**. Two were in `core/`, which `janus-runtime` loads at startup.

| File | Defect | Fix |
|---|---|---|
| `core/janus_avatar.lua` | Invalid escape `\ ` in ASCII art | Escaped the backslash |
| `core/janus_voice.lua` | Unary `+` (not valid Lua) in 19 places | Removed unary plus |
| `plugins/06_game_god.lua` | Invalid escape `\;` | Escaped the backslash |
| `src/lua/ai_manager_enhanced.lua` | C-style `//` comment on line 1 | Changed to `--` |

**Verified:** all 10,634 files now compile (0 failures, 0 unverified).

### Stage 2 — Quick-start path (FIXED, not runtime-verified)

The README's `cargo run --bin janus-web` → `localhost:5000` path had defects that
made it fail or mislead, especially on Replit:

| Defect | Impact | Fix |
|---|---|---|
| `ws://${location.host}/ws` hardcoded | **Fatal on Replit.** HTTPS pages block `ws://` as mixed content, so the launcher never connected | Scheme derived from `location.protocol` (`wss:` on HTTPS) |
| Runtime client defaulted to `http://localhost:8080` | **Fatal on Replit.** The browser is not the runtime host; also mixed content | Defaults to same-origin `/runtime-api`; added a server-side reverse proxy |
| Module/static paths relative to CWD | Empty dashboard unless launched from the repo root | `resolve_root()` checks `JANUS_ROOT`, CWD ancestors, manifest dir, exe dir |
| `take(200)` per category | Silently hid ~7,000 installed modules | Raised to 5,000; registry now exposes 10,418+ |
| 203 root-level `plugins/*.lua` in no category | Unreachable from the launcher | Added `omega_core` category |
| Demo mode off by default, with no UI indication | Looked broken; and when on, simulated output looked real | Server sends `server_status`; UI shows a persistent mode banner |
| Browser-supplied module path read directly | Path traversal in demo mode | Canonicalized and confined to the project root |

Also added `JANUS_WEB_PORT` and `JANUS_RUNTIME_URL` overrides.

### Stage 3 — Production execution was non-functional (FIXED, verified in Lua)

**The most serious functional finding.** `janus-runtime`'s sandbox registered no
`janus` table at all. Every one of the 1,233 plugins calls `janus.log`, so **100%
of modules failed** with `attempt to index a nil value (global 'janus')` — even
with a valid license, active engagement, and approved certification.

Reproduced directly:

```
plugins/forensics/data_carver.lua -> RUNTIME_ERR: attempt to index a nil value (global 'janus')
plugins/91_sqlite_recover.lua     -> RUNTIME_ERR: attempt to index a nil value (global 'janus')
core/janus_safety.lua             -> RUNTIME_ERR: attempt to index a nil value (global 'janus')
```

Implemented a real read-only evidence capability (`janus-runtime/src/evidence.rs`)
and exposed it as `janus.evidence.hash|stat|list|read`, with captured
`print`/`janus.log`. Execution moved to `spawn_blocking` so Lua never blocks the
async reactor.

### Stage 4 — Sandbox escape (FIXED, verified)

**Critical security finding.** `Lua::new()` uses `StdLib::ALL_SAFE`, which is
`(1 << 30) - 1` — it excludes only FFI and `debug`, and **still includes `io`,
`os`, and `package`**. Any module could have run `os.execute(...)`, read any file
with `io.open`, or delete evidence with `os.remove`, entirely bypassing the
approved engagement scope.

Fixed by loading only `COROUTINE | TABLE | STRING | UTF8 | MATH` and explicitly
nilling `io`, `os`, `package`, `require`, `module`, `dofile`, `loadfile`, `debug`.

**Verified:** 8/8 escape attempts blocked; legitimate `string`/`math` still work.

### Stage 5 — Authorization gap (FIXED, logic verified)

`EngagementScope::permits_evidence_path` was **dead code**. `authorizes()` only
checked `approved_assets`, so an engagement that approved evidence paths could
never authorize read-only collection — the first family to be certified was
unusable. `authorizes()` now accepts an exactly-matched approved asset **or**
evidence path; the feature must still be approved separately.

Also: `authorize_production_execution` now **returns** the approved scope, and the
API passes it into the sandbox, so execution is confined to exactly the scope that
was authorized rather than re-reading it at the call site.

### Stage 6 — Manifest format was invalid Lua (FIXED, verified)

The `--[{ ... }]` manifest format documented in `plugin.rs` only comments its
first line; the JSON body is parsed as Lua and fails to compile. Rewrote
`extract_manifest_json` to accept a fully `--`-commented block (valid Lua) while
remaining backward compatible, and shipped the new modules in the valid form.

### Stage 7 — JSON conversion (FIXED, logic verified)

`lua_value_to_json` used `pairs::<String, LuaValue>()`, which cannot represent
integer keys, so `evidence.list` results would fail or distort. Rewrote to handle
key types explicitly, emit proper JSON arrays for 1-based sequences, and bound
nesting depth at 32 to stop self-referential tables overflowing the stack.

## 4. Round 2 — additional fixes (2026-11-05, later session)

### Hardware no longer reports fake success (FIXED, uncompiled)
`janus-runtime/src/hardware.rs` was rewritten. Previously `SerialInterface::write`
returned a byte count without writing, `read` returned `0`, cellular and RF scans
returned empty `Vec`s (indistinguishable from "nothing found"), and sensors
returned fabricated `(0, 0, 9.8)` / `(0, 0)` readings. **Every unimplemented
operation now returns `Err`** naming the adapter and operation. `available()`
reports only whether a device node exists — it does not claim the device works.
`initialize()` still returns `Ok` when hardware is absent (that is normal) but
logs a warning and claims no capability. 9 async tests added.

### Core loader no longer claims false success (FIXED, uncompiled)
A wasmoon probe showed **all 22 `core/*.lua` files fail** with
`attempt to index a nil value (global 'janus')`, yet startup logged "initialized
with core modules". `LuaEnv::new()` now uses the same `new_sandbox_lua()` as
plugin execution, and `load_core_modules` returns `CoreLoadReport { loaded, failed }`
which is logged honestly. Core modules get a capture-only `janus.log` and **no
evidence API** — loading `core/` grants no capability. 3 tests added.

### Read-only evidence family completed — now 5 modules
Added `evidence.read` (bounded hex slice, max 1 MiB) and `evidence.manifest`
(chain-of-custody: hashes every regular file, records `symlink_not_followed`,
`directory_not_recursed`, and `unreadable` instead of silently skipping).
The Lua behaviour suite is now **29/29 passing**, including a symlink escape that
is refused and recorded. `scripts/certify-evidence.py` emits the exact module IDs
and SHA-256 hashes a reviewer must approve, plus ready-to-run `curl` calls. **It
certifies nothing itself** — certification remains a human Reviewer decision.

### Legacy web executor reported crashed modules as successful (FIXED, uncompiled)
Real bug: the executor pushed `[LUA ERROR] {e}` while the WebSocket handler tested
`starts_with("[ERROR]")`, so a module that raised emitted `module_complete`. Worse,
errors from the implicit `execute()` call were discarded with `let _ =`. Both are
fixed: one shared `MODULE_ERROR_PREFIX` constant, a `module_output_has_error()`
helper used by the handler, and `execute()` failures are now captured. 5 tests added.

### Explicit tenant binding in the execution gate (HARDENED, uncompiled)
`authorize_production_execution` looked up the license by the caller's
organization but fetched the engagement by ID with no organization filter. This
was **not exploitable** — `authorize_execution` rejects a license/engagement
organization mismatch, and the license always belongs to the caller. But the
isolation was implicit and would break if license lookup ever changed. An explicit
`engagement.organization_id != account.organization_id` check now enforces it
directly, with a regression test. Verified the `/execute` handler computes the
module hash server-side and never trusts a client-supplied hash.

### End-to-end integration tests authored (uncompiled)
`janus-runtime/src/integration_tests.rs` — 13 tests against a real temporary
SQLite database, a throwaway Ed25519 key generated per run, and real files:
authorized execution produces the real SHA-256; tampered module hash refused;
out-of-scope target refused; uncertified and `pending_review` modules refused;
operators cannot certify; disabled engagement authorizes nothing; the sandbox
refuses a file outside scope *even after* authorization passed; denials and
successes are both audited; expired licenses cannot be imported; foreign-organization
licenses refused; cross-tenant engagements refused; all 5 shipped modules execute
and leave evidence byte-identical.

### New offline check
`tools/audit/check_rust_structure.py` verifies Rust delimiter balance with a lexer
that correctly skips raw strings, char literals, lifetimes, and comments. A naive
regex counter produced false positives; this does not. **33/33 files clean.** It is
now stage 5 of `verify.sh`. It is explicitly *not* a compile check.

## 5. What remains unfinished

**Blocking**
1. **Run `cargo check --workspace` and `cargo test --workspace`.** All Rust changes
   remain unverified by a compiler. 58 Rust tests are authored and none have run.
   This is the first thing to do.

**Known incomplete (honestly reported, not simulated)**
2. `evidence_readonly` is implemented and tested but **not yet reviewer-certified**.
   Run `python3 scripts/certify-evidence.py --curl` to produce the review sheet,
   review the code, then record `production_approved` as a Reviewer.
3. **No production hardware drivers.** All adapters now correctly report
   `unsupported` rather than faking success. Nothing here is certifiable.
4. `operation_approvals` table exists but is unused; no approval workflow.
5. The bulk Lua library (~10,600 files) remains **uncertified demo content**. Most
   files only print strings. `plugins/91_sqlite_recover.lua`, for example, prints a
   hardcoded "Password identified: 'janus2026'" — it recovers nothing.
6. `janus-web/src/dashboard.rs` is dead code (never declared as a module).
7. Two `mlua` versions are vendored (0.9 for runtime, 0.10 for web), building Lua
   twice. Worth unifying.
8. License revocation/refresh is documented in the plan but not implemented;
   `find_active_license` picks the newest import and relies on expiry checks.
9. **No DoS limits on plugin execution.** The sandbox blocks `io`/`os`/`package`
   escapes, but a module can still spin forever or allocate without bound. mlua
   instruction-count and memory hooks are not yet installed.
10. License signing uses `serde_json::to_vec(&claims)`, so signature validity
    depends on field order staying stable. A canonical encoding would be safer.

**Not touched, per instruction**
- `.github/workflows/` — read only, never modified. Note `rust-ci.yml` runs only
  `cargo check` and a release build; it **never runs `cargo test`**. Adding tests
  to CI would need your approval.

2. Reviewer-certify the five `evidence_readonly` modules by exact SHA-256 using
